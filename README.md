# GodjiScanner 0.6.0

Сканер установленного контента для Windows 10/11 x64. Предназначен для вызова из существующего агента GodjiOS независимо от его языка: отдельный процесс, UTF-8 JSON и стабильные коды завершения. Первая версия — консольный модуль, без графического интерфейса.

## Быстрый запуск

**Без каталога и без команд:** распакуйте архив и дважды щёлкните `GodjiScanner.exe`. Автоматически начнётся поиск в Steam, Epic, реестре, ярлыках и на всех локальных несъёмных дисках. После сканирования откроется окно ручного отбора; его решение сохраняется в `review.json` рядом с результатом. Устанавливать Python и класть рядом пример каталога не нужно.

Дождитесь завершения и откройте папку `results/scan-ДАТА-ВРЕМЯ` рядом с EXE:

- `report.html` — таблица результатов для просмотра в браузере, разбитая на приложения, кандидаты и компоненты игр;
- `scan.json` — полный результат для передачи разработчику или дальнейшего экспорта;
- `applications.csv` — таблица рекомендуемых карточек для Excel;
- `scan.log` — журнал поиска.

Окно остаётся открытым до нажатия Enter. Отмена — Ctrl+C; при обычной отмене сохраняются частичные результаты. Если закрыть окно крестиком или принудительно завершить процесс, сохранение не гарантируется. Если папка с EXE недоступна для записи, результаты сохраняются в `%LOCALAPPDATA%/GodjiScanner/results`; точный путь выводится в окне. Каждый запуск создаёт новую папку.

Автоматический режим проверяет до 2 000 000 файлов, пропускает системные папки и безопасно проходит локальные ссылки, не зацикливаясь. В главный раздел попадают игры, игровые лаунчеры, ПО мышей, клавиатур, гарнитур, видеокарт и аудио, а также встроенные настройки Windows. Обычные программы из ярлыков и реестра остаются в разделе «Кандидаты» до ручного добавления в каталог; установщики, деинсталляторы и внутренние EXE игр — в разделе «Компоненты». Данные не удаляются и остаются в `scan.json` и закрытых разделах HTML-отчёта.

В отчёте автоматически извлекаются локальные PNG-иконки из EXE и ярлыков. Для чистого экспорта GodjiOS эти иконки можно включить как `covers/local-*.png`. Скaнер ничего не скачивает: качественные игровые обложки по каталогу внешних источников — следующий отдельный этап.

Готовый файл: `dist/GodjiScanner.exe`. Python на целевом ПК не нужен. Откройте PowerShell в папке с EXE:

```powershell
# Автоматический поиск в системных источниках, без списка
.\GodjiScanner.exe scan --output .\scan.json

# Поиск с каталогом GodjiOS и дополнительными папками
.\GodjiScanner.exe scan --catalog .\21vek-applications.zip --root D:\Games --root E:\Games --output .\scan.json

# Расширенный поиск по всем локальным несъёмным дискам
.\GodjiScanner.exe scan --all-drives --max-files 2000000 --output .\scan.json

# Экспорт по исходному каталогу с сохранением обложек
.\GodjiScanner.exe export --scan .\scan.json --catalog .\21vek-applications.zip --output .\godjios-import.zip

# Без исходного каталога
.\GodjiScanner.exe export --scan .\scan.json --output .\new-catalog.zip

# Подготовить безопасные предложения для будущего API GodjiOS
.\GodjiScanner.exe proposals --scan .\scan.json --catalog .\21vek-applications.zip --machine-id pc-46 --output .\launch-proposals.json

# Открыть окно ручного отбора после сканирования
.\GodjiScanner.exe review --scan .\scan.json

# Выбрать клуб: из локального ZIP или прямо из Godji Cloud API
.\GodjiScanner.exe clubs

# Тот же сценарий без окна — для агента или автоматизации
.\GodjiScanner.exe club-scan --catalog .\clubs\Бор.zip --output-dir .\club-results\Бор --all-drives

# Сканирование каталога клуба прямо из Cloud. Ключ задаётся только через переменную окружения.
$env:GODJI_MANAGER_API_KEY = "ваш_ключ"
.\GodjiScanner.exe cloud-club --club-id bor-izumrud --output-dir .\club-results\Бор --all-drives
```

Для экспорта указывайте новое имя ZIP: существующие архивы не перезаписываются. Каталог клуба нужно сканировать именно на игровом ПК. Результаты с другого компьютера не подтверждают установку в клубе.

## Что находит эта версия

| Источник | Поведение |
|---|---|
| Steam | Читает библиотеки и манифесты, проверяет папку игры, наличие клиента и флаг завершённой установки. Возвращает Steam EXE и `-applaunch AppID`. |
| Epic Games | Читает локальные манифесты и проверяет игровой EXE. Способ запуска требует проверки: отдельным играм нужен лаунчер. |
| Реестр Windows | Читает пользовательские и системные записи 32/64 bit. Существующий EXE из DisplayIcon считается кандидатом, а не гарантированным способом запуска. |
| Ярлыки | Читает EXE, аргументы и рабочую папку из меню «Пуск» и рабочих столов текущего пользователя и общих папок. Ярлыки не запускаются. |
| BAT/CMD и URL | Находит команды и `.url`-ярлыки, включая игровые URI. Они всегда требуют проверки способа запуска. |
| Команды Windows | Добавляет Звук, микшер, настройки мыши, разрешения и герцовки как встроенные карточки Windows. |
| Пути шаблона | Проверяет существование указанного EXE и добавляет кандидата для проверки. Для Steam-игр одного EXE клиента недостаточно. |
| Папки и диски | По `--root` или `--all-drives` ищет EXE, BAT/CMD и URL. Результаты требуют проверки. |

Режим без списка работает самостоятельно. Каталог нужен только для сопоставления с желаемыми играми и сохранения оформления. Для простого списка можно создать JSON с `items`, где у каждой записи есть уникальный `id` и `title`; пример — `examples/wanted.json`.

`found` означает наличие достаточных локальных признаков установки, а не проверенный запуск: сканер не запускает игры и не проверяет лицензии или аккаунты. `needs_review` — кандидат; `not_found` встречается в сопоставлении с каталогом и означает, что выбранные источники не дали подходящего результата.

## Проверка и экспорт

По умолчанию экспортируются подтверждённые находки. При работе с шаблоном ненайденные и неподтверждённые записи сохраняются с `visible: false`. У подтверждённых записей сохраняется прежний флаг видимости: ранее скрытые игры сами не включаются. Категории, ID, дополнительные поля и исходные обложки сохраняются.

Просмотрите `items` и `matches` в JSON. Для проверенного кандидата передайте его `detected-…` ID:

```powershell
.\GodjiScanner.exe export --scan .\scan.json --output .\approved.zip --approve detected-0123456789abcdef
```

Для скана по каталогу добавьте `--catalog` с тем же файлом. `--approve` можно повторять. Если у записи несколько кандидатов, сначала выберите нужный `itemId` из её `candidateIds` в копии JSON, затем подтвердите этот ID. Перед подтверждением можно исправить `title`, `type`, `launch.path`, `launch.args` в копии результата. При `preserveArgs: true` экспорт использует аргументы шаблона; чтобы использовать отредактированные аргументы находки, смените `preserveArgs` на `false` у соответствующего сопоставления.

Сопоставление Steam использует AppID. Один установленный лаунчер не подтверждает установку всех игр из каталога. Остальные сопоставления используют название или имя EXE; сомнительные и неоднозначные результаты не подтверждаются автоматически.

`proposals` создаёт JSON для будущего write API GodjiOS. В него попадают только однозначные находки с высокой уверенностью и только когда путь или аргументы отличаются от карточки каталога. В каждом предложении есть `applicationId`, прежний путь, новый способ запуска, идентификатор ПК и скана. Команда ничего не отправляет в Cloud и не меняет каталог.

`review` открывает окно для ручного отбора. Можно включать и исключать записи, искать их по названию или пути, а также назначать запуск на клиентских ПК, сервере либо на всех ПК. По умолчанию включены только рекомендуемые карточки; CCBoot, ClubMonitor, Godji и пути серверного ПО назначаются серверу. Результат сохраняется рядом со сканом как `review.json`.

`clubs` — сценарий реального клуба. В окне нажмите «Загрузить из Cloud…», введите Manager API key, получите список доступных клубов и выберите нужный. Ключ используется только в памяти текущего запуска и не записывается в отчёты, ZIP или настройки. Сканер загружает каталог клуба вместе с его обложками, обходит локальные источники и диски, а в `scan.json`, отчёт и `godjios-import.zip` включает только карточки выбранного клуба. ID, категории, обложки, исходные аргументы и другие поля сохраняются. Отсутствующие программы сохраняются в импорте скрытыми; по умолчанию неоднозначные кандидаты не подставляются.

Можно по-прежнему положить ранее экспортированный ZIP в `clubs`, например `clubs/Бор.zip`, и выбрать его офлайн. Если папка `clubs` с каталогами лежит рядом с EXE, достаточно дважды щёлкнуть `GodjiScanner.exe` — сразу откроется выбор клуба. Без локального ZIP запустите `GodjiScanner.exe clubs` и выберите Cloud API.

При экспорте без шаблона создаётся каталог версии 3 без обложек и категорий, с пустым `clubId`. Импорт такого каталога и допустимость пустого `clubId` ещё нужно проверить на тестовом GodjiOS. При необходимости задайте `clubId` в JSON результата перед экспортом. Поддержка полей ZIP основана на предоставленном образце, а не на документации импортера.

## Ограничения первой версии

- Нативные адаптеры Riot, Battle.net, EA, Ubisoft, GOG, Lesta и Microsoft Store пока не реализованы. Их пути могут обнаруживаться через ярлыки, реестр и поиск по папкам.
- Без `--root`/`--all-drives` произвольные portable-приложения вне системных источников могут остаться ненайденными.
- В `--all-drives` пропускаются системные/служебные папки и вложенные символические ссылки/junction. По умолчанию обход ограничен 200 000 файлов; достижение лимита или ошибки доступа дают `partial: true` и предупреждения.
- Не выполняется нечёткое сопоставление разных написаний названий. Карточки с одним путём, но разными аргументами или рабочими папками намеренно не объединяются.
- Рабочая папка сохраняется в JSON, но в ZIP не переносится: в образце GodjiOS нет соответствующего поля. Для приложений, которым она необходима, понадобится уточнение контракта импортера.
- Работа от службы SYSTEM увидит системные источники и профиль SYSTEM. Для пользовательских библиотек и ярлыков запускайте процесс в контексте игрока либо явно передавайте папки. Все пользовательские профили автоматически не обходятся.
- EXE не подписан. В этой среде проверен на Windows 11; отдельная проверка Windows 10 и импорта в GodjiOS ещё требуется.

## Разработка

Ядро написано на Python, но интеграция использует только процесс и JSON. Зависимостей времени исполнения, кроме стандартной библиотеки, у исходников нет. Сборка EXE включает интерпретатор.

```powershell
python scanner.py scan --output .\scan.json
python -m unittest discover -s tests -v
python -m pip install -r requirements-build.txt
.\build.ps1
```

Собрано с Python 3.14.6 x64 и PyInstaller 6.21.0. Подробный контракт: `docs/INTEGRATION.md`. JSON Schema: `docs/scan-result.schema.json`.
